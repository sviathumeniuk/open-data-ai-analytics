# Звіт по лабораторній роботі 3

## Посилання на репозиторій

**Repository:** https://github.com/sviathumeniuk/open-data-ai-analytics

## Мета роботи

Перевести попередній монолітний Python-проєкт у сервісну архітектуру з окремими контейнерами для кожного етапу пайплайну обробки даних та забезпечити локальний запуск усієї системи однією командою.

## Реалізована архітектура

Проєкт розділено на окремі сервіси:

1. `db` — централізоване сховище даних і результатів.
2. `data_load` — читає CSV з `raw/`, створює таблицю та імпортує записи в `vat_registry`.
3. `data_quality_analysis` — обчислює метрики якості даних і зберігає їх:
   - у таблицю `data_quality_metrics`;
   - у файл `reports/data_quality/latest.json`.
4. `data_research` — виконує дослідницьку аналітику, зберігає результати:
   - у таблицю `research_results`;
   - у файл `reports/data_research/summary.json`.
5. `visualization` — генерує графіки у `reports/figures/*`.
6. `web` — надає веб-інтерфейс для перегляду метрик, результатів дослідження та фігур.

## Контейнеризація

Для кожного сервісу створено окремі файли:

- `Dockerfile`
- `requirements.txt`
- `app.py`

Контейнери зібрані на базі `python:3.11-slim`, що забезпечує компактний розмір і передбачуване оточення.

## Оркестрація через Docker Compose

У `compose.yaml` описано:

- залежності між сервісами (`depends_on` з умовами `service_healthy` та `service_completed_successfully`);
- мережу `analytics_net`;
- volume для БД (`db_data`);
- bind mounts для обміну результатами (`./reports`) і для доступу до вхідного CSV (`./raw`);
- змінні середовища для підключення до БД;
- публікацію порту `8000` для веб-інтерфейсу.

## Обмін результатами між контейнерами

Реалізовано комбінований підхід:

1. **База даних** — передача структурованих результатів між `data_load`, `data_quality_analysis`, `data_research`, `web`.
2. **Спільний том** — передача артефактів у вигляді JSON-файлів і зображень (`reports/*`) між аналітичними сервісами, візуалізацією та веб-інтерфейсом.

Це дозволяє зберігати як машинно-читані, так і людино-читані результати.

## Перевірка працездатності

Виконано локальний запуск:

```bash
docker compose up --build
```

Результат:

- сервіси `data_load`, `data_quality_analysis`, `data_research`, `visualization` виконуються як batch-етапи і завершуються успішно;
- сервіс `web` залишається активним і доступний за адресою `http://localhost:8000`;
- HTTP-перевірка відповіді веб-сервісу повертає `200 OK`.

## Підсумок

У лабораторній роботі 3 виконано повний перехід від локально-зв’язаного коду до контейнеризованої сервісної архітектури. Отримано відтворюваний процес запуску, ізольовані середовища для модулів, формалізований обмін даними між компонентами та готовий веб-доступ до результатів аналізу.
