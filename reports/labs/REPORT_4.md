# Звіт по лабораторній роботі 4

## Посилання на репозиторій

**Repository:** https://github.com/sviathumeniuk/open-data-ai-analytics

## Мета роботи

Завершити розробку аналітичної платформи шляхом переходу до моделі **Infrastructure as Code**. Основна мета — автоматизувати створення хмарних ресурсів в **Oracle Cloud Infrastructure (OCI)** за допомогою **Terraform** та забезпечити автоматичне розгортання оптимізованого аналітичного стеку через **cloud-init**.

## Опис хмарної інфраструктури (OCI)

Для мінімізації витрат та стабільної роботи використано ресурси рівня **Always Free**. Конфігурація мережі та обчислювальних потужностей:

| Ресурс OCI                    | Опис та параметри                                               |
| :---------------------------- | :-------------------------------------------------------------- |
| **oci_core_vcn**              | Віртуальна мережа проєкту з CIDR `10.0.0.0/16`.                 |
| **oci_core_subnet**           | Публічна підмережа для доступу до сервісів.                     |
| **oci_core_internet_gateway** | Забезпечує вихід інстансу в інтернет.                           |
| **oci_core_security_list**    | Правила Ingress: порт **22** (SSH) та **8000** (Web Dashboard). |
| **oci_core_instance**         | **AMD Micro Instance** (1 OCPU, 1 GB RAM).                      |

## IaC та автоматизація

Розгортання здійснювалося через **Oracle Cloud Shell** з використанням вбудованої автентифікації `InstancePrincipal`.

### Terraform

У Terraform для передачі SSH-ключа та `cloud-init` використано метадані інстансу:

```hcl
# Фрагмент Terraform метаданих
metadata = {
  ssh_authorized_keys = var.ssh_public_key
  user_data           = base64encode(file("cloud-init.yaml"))
}
```

### cloud-init

Конфігурація **cloud-init** стала ключовим елементом стабільності та автоматизації, виконуючи критичні кроки:

1. **Swap File (2GB):** створення файлу підкачки для запобігання OOM-помилок при роботі Python (Pandas/Matplotlib) на 1 GB RAM.
2. **Системне оточення:** встановлення Docker та Docker Compose Plugin.
3. **Deployment:** клонування репозиторію та автоматичний запуск консолідованого аналітичного пайплайну.

## Хід виконання роботи

Процес розгортання включав наступні кроки у браузерному терміналі Oracle Cloud Shell:

1. **Ініціалізація:** підготовка провайдера OCI (`terraform init`).
2. **Валідація:** перевірка плану створення ресурсів (`terraform plan`).
3. **Розгортання:** створення інфраструктури (`terraform apply`).
4. **Оптимізація коду:** в межах цієї роботи проведено рефакторинг — перехід на **SQLite** та об'єднання всіх етапів обробки даних (load, quality, research, viz) в один послідовний процес (pipeline) для максимальної економії пам'яті.

## Результати та перевірка працездатності

Після успішного завершення `terraform apply` Terraform повернув публічну IP-адресу інстансу.

- **Статус Pipeline:** скрипт `pipeline/run_all.py` успішно відпрацював усі етапи в межах одного контейнера.
- **Доступ до Dashboard:** веб-інтерфейс доступний за адресою `http://79.76.62.101:8000`.
- **Стабільність:** завдяки Swap-файлу та SQLite система працює без збоїв.

## Підсумок

У ході роботи було доведено, що хмарна інфраструктура OCI рівня **Always Free** є достатньою для складних аналітичних задач за умови грамотної оптимізації. Використання **IaC (Terraform)** дозволяє розгорнути готове рішення "з нуля" за кілька хвилин. Перехід на **SQLite** та використання **Swap (2GB)** стали вирішальними факторами для стабільної роботи аналітичного пайплайну на інстансі з 1 GB оперативної пам'яті.
